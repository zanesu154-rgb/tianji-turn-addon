# 索引方案

目标：以后查 LFMC 的历史决定时，先搜几万字节的索引，再按行号从私有档案里取出那一轮。不要把 224,122 行读进一次对话。

索引记录顺序、说话人、工具配对和位置。它不替代档案，也不把当时的回复提升成现行规则。

## 档案不动，索引里不放什么

原始文件保持在 `BUG-Test-addon-world` 的 `The History(Important)/12_天际翻译插件修正.md`。`build_index.py` 只读它，并且只把结果写到 `--out`。

公开的 LFMC 仓库不复制这些东西：

- Bash 命令、Write/Edit 的正文、工具的标准输出
- 对话里贴进来的第三方附加包源码
- 两份嵌进档案的附件正文
- 59 个上传文件的字节和 53 张图片的像素

这些材料留在私有档案的原行。索引用行号指过去。

短预览最多约 240 字，并且会跳过看起来像代码、语言键或工具占位符的行。所以第 68 条消息的预览是空的，原文仍在它的 `lines` 里。

## 文件

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 档案 SHA-256、行数、计数、空消息、异常列表。对不上 SHA-256 就不要用这些行号 |
| `messages.jsonl` | 395 条消息，顺序就是档案顺序。每条有编号、角色、UUID、台北时间、行范围、预览、主题、块计数 |
| `chapters.jsonl` | 195 章。一章是一条用户消息，加上它后面连续的助手消息，直到下一条用户消息 |
| `blocks.jsonl` | 7,612 个内容块。思考块带摘要；续写文本块带短预览；「与消息文本相同」的块不再抄一遍 |
| `tool-pairs.jsonl` | 2,618 对。`tool_use_id` 把调用和结果连起来，两边都有行号。只有 `is_error` 才留一句错误短摘 |
| `tool-errors.json` | 那 32 次 `is_error` 的短摘，方便先扫失败 |
| `attachments.jsonl` | 文档、图片、两份文本附件的位置和标题。`bytes_in_archive` / `pixels_in_archive` 标明有没有实体 |
| `topics.json` | LFMC 与其他仓库的区分、主题解释、每条主题落在哪些用户消息、第 392 条样包对照的指针 |
| `lookup.py` | 按主题、错误、消息号或行号读取。默认最多打印 400 行 |
| `build_index.py` | 从档案重建上面的 JSON。不写回档案 |

一条 JSONL 记录上的 `channel` 和 `epistemic` 是给检索用的分类，不是档案原文里的字段。

## 一轮对话在索引里怎么摆

以第 1 章为例，顺序是：

1. `chapters.jsonl` 里 `chapter: 1` 指向用户消息 1 和随后的助手消息，并给出整章行范围。
2. `messages.jsonl` 里 `n: 1` 是用户要求，`n: 2` 是助手开头的那段话。
3. 助手消息正文里的 “This block is not supported…” 不单独成记录。同一次消息里的 `tool_use` 块才是调用。
4. `tool-pairs.jsonl` 用 `tool_use_id` 找到同消息里的 `tool_result`。失败尝试看 `is_error`，不要只看助手最后一段「已经修好」。
5. 工具跑完后的说法在 `blocks.jsonl` 里 `type: "text"` 且 `text_class: "continuation"` 的块。206 个写着「与消息文本相同」的文本块没有新内容。
6. 用户下一条消息如果改口，新的一章覆盖上一章的说法。两条都留着。

空助手消息 45、49、69、136、191、250、311 也占编号。不要把编号对到「下一条有字的回复」就算作这一条。

## 建议的查法

1. 用 `lookup.py --topic <名字>` 或直接搜 `chapters.jsonl`。主题名字以 `topics.json` 的 `topic_defs` 为准。
2. 失败和报错先看 `lookup.py --errors`，再决定要不要打开那一对工具的行。
3. 样包归属先打开用户消息 392，再看 `attachments.jsonl` 的标题。样包不是独立项目。
4. 确认行号仍属于这份档案：`lookup.py` 默认核对 SHA-256。
5. 用 `--message` 或一个窄的 `--lines` 取出原文。一次只取回答当前问题需要的那一轮。
6. 读完后按通道下判断：用户原话、工具输出、源码片段、模型摘要，分开引用。模型摘要和助手续写要再对当前代码，才能写成现在的行为。

行号是 LF 行号。不要用会把 U+2028 当成换行的切分方法，否则第 195,541 行之后的编号会错两位。

## 这一阶段没有做的事

没有从对话里抽出「现行设计规格」，没有把失败实验收成结论，也没有改 LFMC 的源码或测试。那些要等下一道指令，并且每次都得回到上面的行号，而不是只凭索引里的短预览。
