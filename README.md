# 栈主的附加包汉化工具

[English](README_en.md) · 简体中文

把 Minecraft 基岩版**附加包**和**世界存档**里玩家能看到的文字提取出来，换成翻译键，生成 `.lang` 语言文件。翻译好 lang 文件后，同一个附加包 / 地图就能按玩家的游戏语言显示。

**在线使用：** <https://zanesu154-rgb.github.io/tianji-turn-addon/>

- 纯网页工具，所有处理都在你的浏览器里完成，**文件不会上传**到任何服务器
- 手机、电脑都能用；界面支持简体中文、繁體中文、English、日本語、한국어、Русский

---

## 快速上手

### 翻译一个附加包

1. 打开网页，选择 **附加包** 标签。
2. 上传 `.mcaddon`、`.mcpack` 或 `.zip`（也可以直接拖进来）。
3. 等进度条完成，查看结果摘要。
4. 点 **下载转换后文件**，得到 `<原名>_i18n.mcaddon`。
5. 点 **下载翻译表**，里面有 `source_<语言>.lang`（全部原文）和 `strings.csv`。
6. 把原文翻译成目标语言，写进附加包资源包 `texts/` 下对应的文件（如 `zh_CN.lang`），重新导入游戏即可。

> ⚠ 请始终用**原始**附加包转换。已经转换过的附加包再转换不会修正之前的提取结果。

### 翻译一个世界存档 / 结构

1. 选择 **世界存档** 标签。
2. 上传 `.mcworld`、`.mctemplate`（手机无法导出存档时可以导出成模板）或 `.mcstructure`。
3. 告示牌、命令方块、NPC、成书等会自动换成翻译键；游戏不支持翻译键的文字（容器名、物品名等）列在下方编辑器里，可直接改成目标语言。
4. 点 **下载转换后文件**。存档会自带一个翻译资源包 `resource_packs/<世界名>_texts/`，打开存档自动加载；翻译它的 lang 文件即可。

> ⚠ 处理存档前请先备份。

## 处理选项

| 选项 | 说明 |
|---|---|
| 原文语言 | 附加包原本是什么语言。默认自动识别 |
| 生成语言文件 | 要生成哪些语言的 lang，逗号分隔，如 `en_US, zh_CN, ja_JP`。另外总会生成 `en_US`（游戏找不到翻译时的回退语言）和包里已有的语言 |
| say / tell / me 命令 | 游戏不会翻译 `say`。默认转成 `tellraw`（显示效果和原来一样，带 `[发送者]` 前缀；`/me` 保留 `* 发送者` 格式）；也可转成屏幕标题、物品栏上方提示，或不转换 |
| 脚本自带翻译字段 | 附加包脚本里自带多语言表时，留空会自动识别；识别错了可手动指定，如 `s=en_US, v=vi_VN`，或按文件指定 `dialogue_es.js:v=es_ES`；填 `off` 关闭 |
| 处理脚本 / 注入运行时翻译 | 是否处理 `scripts/*.js`。运行时翻译用来处理变量、数据表里的文字，一般保持开启 |
| 从其他语言补全缺失键 | 某个语言的 lang 缺少键时，从其他语言复制过来，避免游戏里显示键名 |
| 生成占位名 | 物品 / 方块 / 实体没有名称时，按 ID 生成英文名（创造栏里隐藏的不生成） |
| 列出命令方块名称 | 地图作者常给命令方块起名做标记，默认不列入需人工翻译 |
| 提取创造物品栏里不显示的物品 | 默认关闭：创造栏隐藏的物品 / 方块（`menu_category` 为 `none` 等）和不显示的刷怪蛋（`is_spawnable` 不为 true）的名称不提取、不补全 |
| 删除模板残留的无效语言条目 | 默认开启：语言文件里从模板复制来的别的包的刷怪蛋名、实体名等（键和值都与内置黑名单相同、包里又用不到的）从所有语言中删除 |
| 多行文本拆成多个键 | 默认一段文字一个键，换行写成 `\n`（游戏内实测可正常换行） |

## 会提取哪些文字

### 附加包

| 位置 | 内容 |
|---|---|
| 物品、方块、实体 | 名称、首领血条名、交互按钮文字、交易表 |
| NPC 对话（`dialogue/`） | 名字、正文、按钮 |
| 函数、动画控制器、实体事件里的命令 | `title` / `titleraw` / `tellraw`，`say` 按选项转换 |
| JSON UI（`ui/`） | 界面上显示的文字；只拼进表达式的变量不改，避免界面出错 |
| 脚本（`scripts/`） | 表单标题 / 按钮 / 正文、`sendMessage`、`setActionBar`、`setTitle`、`runCommand` 等；变量、数据表里的文字在游戏运行时翻译 |
| 脚本自带的多语言表 | 同一句话的各语言版本合并成一个键，已有译文写进对应语言的 lang |
| `structures/*.mcstructure` | 与世界存档相同 |
| `manifest.json` | 包名、包描述 |

### 世界存档 / 结构

| 位置 | 处理 |
|---|---|
| 告示牌、悬挂告示牌 | 正反面文字改为翻译键 |
| 命令方块、命令方块矿车 | `title` / `tellraw`，`say` 按选项转换 |
| NPC（含地图自制的 NPC 实体） | 名字、正文、按钮 |
| 成书（箱子、讲台、玩家背包里） | 每页改为翻译键 |
| 存档自带的行为包 / 资源包 | 按附加包方式处理（如 `/dialogue` 用到的对话） |
| 容器名、物品名、物品描述、名字标签、书名、世界名 | 游戏不支持翻译键 → 在编辑器里手动改 |

## 需人工翻译的文字

有些位置游戏只认纯文字，例如战利品表里的 `set_name` / `set_lore`、脚本里的 `nameTag`、存档里的物品名和容器名。这些会出现在结果下方的**编辑器**里：

- **需人工翻译**：逐条直接改成目标语言。顶部可以按类别勾选，取消勾选的类别不显示、不导出
- **导出 / 导入翻译表**：内容很多时，点“导出待翻译表”，用 Excel 等软件在 `translation` 列填好译文，再点“导入翻译表”一次写回。`ref` 列记录位置，请勿修改。Excel 直接保存的 CSV（GBK 编码）也能导入，导入后和原文不同的条目会标“已修改”；下载后再改，再次下载会按最新内容写回
- **日志语言**：处理日志跟随网页右上角的界面语言（简体 / 繁体中文、英语、日语、韩语、俄语），下载的日志也是同一种语言；玩家可见的原文不会被翻译
- **清理存档里的包**（存档模式）：地图里常有没启用的包、同一个包的多份旧版本、没有 manifest 的文件夹，游戏都不会加载，只占空间。转换时日志会列出它们和大小；勾选“删除存档里没启用、重复和无效的包”就会删掉。WorldEdit 这类地图编辑工具另有一个勾选项，删掉时会同时取消启用。uuid 不同但定义了大部分相同实体 / 物品的包（同一附加包的不同版本）会在日志里提示，勾选“同时删除同一附加包的其他版本”只保留登记排最前的
- **存档也一样**：用原始存档再次转换时，把上次输出的 `resource_packs/<名字>_texts/` 整个文件夹（或只把里面翻译好的 `texts/*.lang`）放回原处即可，译文不会被覆盖
- **译完再转换一次**：把翻译好的 lang（例如 `zh_CN.lang`）放回原包的 `texts/` 里重新转换，会沿用上次的键名和你的译文，只补新增的条目，已经用不到的旧键会被删掉。**建议把上次输出的 `en_US.lang` 和译文 lang 一起放回去**：这样按原文逐条核对；只放译文时按键的顺序对应，附加包或本工具更新后顺序可能变，译文会错位
- **搜索 / 浏览全部**（存档）：按键名或内容查找存档里的任何 NBT 数据并修改，例如搜索 `CustomName` 批量改名字

所有修改在点击“下载转换后文件”时写回。

游戏限制提示：成书每页最多 256 个字符、14 行，最多 50 页，书名最多 16 个字符。编辑器会显示字数，超长的页会自动分页。

## 常见问题

**结果里的「最低可用版本」怎么算的？**
附加包取三项中最高的：manifest 的 `min_engine_version`（作者自己填，常偏低，只作参考）、脚本 API `@minecraft/server` 版本对应的游戏版本（按官方对照表）、items / blocks / entities 等文件里最高的 `format_version`（游戏不加载比自身新的文件）。用了 `-beta` 测试版脚本 API 的，只能在对应的那一个版本开启「测试版 API」实验性玩法运行，会单独提示。世界存档直接读 `level.dat` 的 `MinimumCompatibleClientVersion`；存档自带的包要求更高时取更高的。

**翻译完进游戏还是显示原文？**
确认翻译写进了**资源包**的 `texts/` 下对应语言的文件（如 `zh_CN.lang`），并且资源包已启用。行为包里的 lang 只对包名、包描述生效。

**游戏里显示一串键名，比如 `item.xxx.name`？**
说明当前语言的 lang 里缺这个键。开启“从其他语言补全缺失键”重新转换，或在该语言的 lang 里补上。

**lang 里的 `%1$s`、`§a`、`\n` 是什么？**
`%1$s` 是游戏运行时填入的内容（玩家名、数字等），翻译时保留，可以调整位置，但**不要改成 `%s`**；`§a` 等是颜色码；`\n` 是换行。

**附加包自带的“语言设置”不起作用了？**
转换后显示的语言改为跟随游戏语言，附加包内的语言选项基本不再生效，翻译内容不变。

**页面一直显示旧版本 / 提示刷新？**
GitHub Pages 有缓存，强制刷新页面或清除该网站的缓存。页面底部会显示当前版本号。

## 已知限制

- 混淆过（文字被编码）的脚本无法提取
- 玩家在聊天里输入的内容不经过 lang，聊天关键词只能由作者在正则里加上其他语言的说法
- 翻译表（下载的报告）里的原因说明目前只有中文；网页上的处理日志已跟随界面语言
- 访问计数使用第三方统计服务“不蒜子”，只统计页面访问，不涉及你的文件；加载失败时不显示

## 本地运行与开发

直接用浏览器打开 `index.html` 即可（需要联网加载 JSZip）。

```
node test/run-tests.js   # 端到端测试，需要 Node 18+
```

```
index.html / style.css / app.js   界面、zip 读写
src/ui-i18n.js        界面语言
src/util.js           文本判定、键名、lang 读写
src/context.js        分配键、去重、报告
src/commands.js       命令改写
src/json.js           物品、方块、实体、对话、UI、manifest
src/script.js         脚本（基于 AST）+ 运行时翻译
src/pipeline.js       附加包主流程
src/world/            存档：NBT、LevelDB、转换、编辑器
vendor/acorn.js       JavaScript 解析器
test/                 测试附加包与测试脚本
```
